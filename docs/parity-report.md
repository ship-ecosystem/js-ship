Node replaces PHP-specific runtime integrations. Octane, Reverb, Dusk, Composer and
PHP framework consoles are deliberately absent. BullMQ, Socket.IO and ws require
app-owned handlers/authentication and run as processes; WebdriverIO uses Selenium
as a runner/client. Ship does not invent business code or install application SDKs.

  CLI subprocesses, terminal navigation/restoration, configuration, schemas,
  framework/output planning, release failure boundaries and extension validation.
  Supported isolated Node 24.22.3 was used; system Node was not changed.
- `npm run check:spec -- ../com.ship.spec`: both canonical schema copies and the
  shared release checker match the local source of truth.
- Shared-spec example tests passed, including a new JS configuration and a release
  fixture generated by js-ship with mocked image export (clearly marked non-runnable).
- Installed 157-file tarball consumer checks passed locally, including CLI, public API/types,
  offline editor schemas and application initialization/validation. The installer
  uses the cache populated by npm ci; runtime prompt dependencies are included.
- All seventeen added server providers passed real container readiness checks.
  MySQL/MariaDB executed app-user queries; Selenium executed a headless WebDriver
  browser command. Elasticsearch needed an explicit test-only disk allocation
  override because this shared host was already above its high disk watermark.
- A real Node/PostgreSQL/Redis release passed the shared complete-folder checker
  and source-free startup. A separate copied-artifact transfer rehearsal removed
  source and the app image before loading/starting without SDK, build or registry
  access (the transfer fixture contains no registry services).
- Actual Playwright browser-server connectivity and Cypress `ship test` passed
  against a renamed app. Cypress's standard defineConfig import works with an
  isolated runner dependency volume; custom plugins still need runner dependencies.
- Live npm → pnpm → Yarn switches passed with rebuilds and matching versions/locks.
- Isolated Mutagen passed initial sync, frozen install, HTTP readiness, source reload
  and session teardown; the temporary daemon was stopped afterward.
- Offline npm release preview passed without publication. Documentation file links
  and Git whitespace checks passed before closure.

The initial Elasticsearch run and the initial Selenium image-download timeout are

Compatibility choices preserve existing js-ship projects: production Compose names
retain `-production`, existing PostgreSQL/Redis/MongoDB version families and volume
identities remain in place, and PostgreSQL accepts its earlier `DB_NAME`/`DB_USER` names as aliases.
These avoid silently moving or major-upgrading persisted data. They are documented
producer compatibility differences; adopting new database majors or renaming data
is a separate migration, not an automatic consequence of ecosystem alignment.

## Remaining release gates and limits

No GitHub push, npm publication, tag creation or visibility change occurred.
All four package Actions workflows were read back as `disabled_manually`; none
was enabled or dispatched. Dependabot update checks remain active. New CI checks
are prepared in local files for the eventual authorized run.

Publish the local shared-spec changes and coordinate other producers' schema-copy
refreshes before relying on the remote canonical schema. Final candidate CI,
public repository/npm setup and a real deployment-tool integration run remain
explicit release steps. Earlier multi-platform/framework CI is historical and
does not certify this revision. The release contract is still an ecosystem draft.

Support is bounded by [framework modes](frameworks.md), [workspaces](workspaces.md),
[services](services.md) and [roadmap](roadmap.md). Arbitrary framework versions,
Gatsby SSR/DSG, other isolated SSR workspace layouts, Bun/Yarn Plug'n'Play, custom
Cypress plugin dependency installation, provider upgrades/backup restoration and
production load/high availability are not implied by these local checks.
